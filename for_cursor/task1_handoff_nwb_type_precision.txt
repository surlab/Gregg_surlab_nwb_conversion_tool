Context
-------
`scripts/run_surlab_format_validation.py` type-checks SurLab cells against
`sur_nwb_conversion_table.csv` column `nwb_type`. When `nwb_type` is too vague
to enforce, the validator records a **table_gap** (warn), not a data failure.
We need Task 1 to make those types concrete enough to validate (or explicitly
mark them nwb_type=N/A to skip type-check — not the same as
nwb_fieldname=validate_only, which still type-checks).

-------------------------------------------------------------------------
Resolved: use float_or_str; document numeric vs string vs empty; point at
quality_metric companion field.

Issue 2 — `nwb_type=array` / coarse array tokens
------------------------------------------------
Resolved: element-qualified types only. Length notes on layout indices.
data_array/timestamps_array: presence + loadable + basic dtype (+ shape when
schema/timestamps allow).

Out of scope

- trialInfo correct / trial_type (still open)

Success criterion
-----------------
No table_gap rows whose detail is only nwb_type='variable' not validated or
bare nwb_type='array' not validated, unless intentionally nwb_type=N/A.
