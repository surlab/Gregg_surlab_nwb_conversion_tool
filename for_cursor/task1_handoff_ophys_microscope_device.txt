Background — how detailed is NWB Device naming for microscopes?
===============================================================================

PyNWB / community practice (see PyNWB ophys tutorial, NeuroConv ophys metadata):

**`Device.name`** — short, stable **instrument identity**, human-readable:
  - Examples: `Thorlabs Bergamo II`, `Bruker Ultima`, `Femtonics Atlas`
  - Used for linking `ImagingPlane.device` and for searching archives by scope
  - **Not** typically a full config string (galvo/resonant/piezo stack, year,
    every addon). That belongs in **`Device.description`** or structured fields.

**`Device.description`** — free text (optional but recommended):
  - Mods, resonant vs galvo path, acquisition software note, room/rig nickname
  - Example: `Two-photon; resonant + galvo; Prairie View 5.4`
  - PyNWB also supports `was_generated_by` for software versions (optional future)

**`DeviceModel`** (PyNWB 3+, optional structured layer):
  - `manufacturer` (e.g. Bruker, Thorlabs, Femtonics)
  - `model_number` / model name (e.g. `Ultima`, `BERGAMO`)
  - Linked from `Device.model` — useful for cross-file search
  - SurLab may add manufacturer/model as **optional** separate columns if Task 1
    wants structured round-trip; otherwise description-only is acceptable v1.

**What SurLab already has (do not conflate with Device.name):**
| Existing field | Typical content | Current / intended NWB home |
| -------------- | --------------- | --------------------------- |
| `{datatypeID}_objectives` | `16X_0.8NA` | `SurLabSchema_<datatypeID>` |
| `{datatypeID}_detection_software` | `Suite2p`, `Prairie View` | SurLabSchema (software ≠ hardware) |
| `{datatypeID}_laser_name` | laser line label | SurLabSchema |
| `{datatypeID}_indicator` | `GCaMP8m` | OpticalChannel.name / ImagingPlane.indicator |
| FOV / pixel_size fields | geometry | SurLabSchema or ImagingPlane when honest |

**Naming convention recommendation for SurLab (Task 1 to lock in docs):**
- **`{datatypeID}_microscope`** (recommended sessionInfo column): value like
  `Bruker_Ultima`, `Femtonics_Atlas`, `Thorlabs_Bergamo_II`
  - snake_case or spaces OK in CSV; converter sanitizes for NWB if needed
  - Same physical scope → **repeat the same string** on each traces stream
    (`GCaMP8m_traces_microscope`, `Neuropil_traces_microscope`, …)
- **Avoid** as `Device.name`: long rig strings such as
  `2015_bruker_ultima_with_res_galvo_and_piezo` unless a lab explicitly
  standardizes on that as their short ID — prefer that text for
  **`{datatypeID}_microscope_description`** instead.

**Multi-stream / shared scope:**
- One NWB `Device` per distinct `{datatypeID}_microscope` **value** in a
  session (Task 2 dedupes by name, same pattern as shared `Neuropixel1.0`).
- Separate `{datatypeID}` streams still get separate ImagingPlanes /
  OpticalChannels / RoiResponseSeries even when they share one microscope Device.

Locked placement (proposed — Task 1 confirm or adjust)
===============================================================================

A) Microscope identity → stock Device (per traces stream, deduped by value)
| SurLab (canonical) | NWB |
| ------------------ | --- |
| `{datatypeID}_microscope` (sessionInfo, **recommended**) | `NWBFile/devices` → **`Device.name`** |
| optional legacy mirror: `{datatypeID}_schema.json` key `microscope` | same target (dual-read; fail if both disagree) |
| (derived) | `ImagingPlane.device` → that Device object for this stream’s plane |

Rules:
- **Stream-scoped sessionInfo column** header = full datatype ID prefix, e.g.
  `GCaMP8m_traces_microscope`, `Neuropil_traces_microscope` (same pattern as
  `{datatypeID}_indicator`, `{datatypeID}_detection_software`).
- **Requirement level:** `recommended` when `*_traces` stream flag is 1
  (warn if missing; do not fail whole session — fallback marker still valid).
- Task 2 creates **one Device per distinct name** in the file; reuses existing
  Device if another stream (or earlier session handler) already registered it.
- Remove / supersede table implication that `{datatypeID}_device` is the
  permanent NWB name — that was a Task 2 scaffolding placeholder only.

B) Optional extended hardware text (v1 — pick one approach)
| SurLab | NWB |
| ------ | --- |
| `{datatypeID}_microscope_description` (optional, plain text) | `Device.description` |
| OR fold into description from schema mirror key `microscope_description` | same |

Rules:
- Free-form rig notes (galvo/resonant, piezo, objective turret, room label).
- **Do not** duplicate `{datatypeID}_detection_software` here — acquisition
  software stays SurLabSchema / separate column (Suite2p ≠ microscope).

C) Optional structured model (v2 — Task 1 may defer rows to “future”)
| SurLab | NWB |
| ------ | --- |
| `{datatypeID}_microscope_manufacturer` | `DeviceModel.manufacturer` or Device.description |
| `{datatypeID}_microscope_model` | `DeviceModel.name` / `model_number` |

If deferred: note in docs that v1 is `microscope` + optional
`microscope_description` only; structured DeviceModel can be a follow-up handoff.

D) Unchanged (explicit non-goals for this handoff)
- ImagingPlane `location`, `grid_spacing`, `origin_coords` — still
  `MISSING_REQUIRED_FOR_NWB` or SurLabSchema when SurLab lacks honest values.
- OpticalChannel / indicator / emission_lambda — unchanged rows.
- ROI metadata (`roi_x_coordinates`, `roi_center_x`, …) — unchanged.
- No session-level aggregate `microscope` column (prefer per-stream repeat;
  same value across streams is OK).
