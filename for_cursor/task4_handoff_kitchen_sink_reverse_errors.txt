Executive summary
===============================================================================

Primary reverse defect: **`nwb_table_reader.py` resolves ecephys Device fields
from the wrong Device** (`_first_device()` → first inserted device, often
`GCaMP8m_traces_device`), instead of the **shared probe Device**
(`Neuropixel1.0`).

Secondary defects:
- `sorting_software` read from **`_first_processing_module()`** (`behavior`)
  instead of probe `Device.description`.
- `spikeWaves_sample_frequency__Hz` reader looks for **Units column** instead
  of **`Units.waveform_rate`**.
- **behEvents** `data_unit_measurement` exports full description string instead
  of parsed token `time__s`.
- **trialInfo** float formatting (`10.000` vs `10`) — validator or export
  formatting, not wrong NWB data.
- **spikeWaves `area`** — spec being removed; reverse should stop exporting it
  after Task 1 table update.

===============================================================================
§1 — Probe / Device fields (HIGHEST PRIORITY)
===============================================================================

**Report symptoms** (`likely_owner=task2_forward` but reverse bug):
| SurLab field | Original | Broken roundtrip | Wrong source |
|--------------|----------|------------------|--------------|
| `spikeTimes_probe` | Neuropixel1.0 | GCaMP8m_traces_device | `_first_device()` |
| `spikeWaves_probe` | Neuropixel1.0 | GCaMP8m_traces_device | same |
| `lfp_schema.probe` | Neuropixel1.0 | GCaMP8m_traces_device | same |
| `spikeTimes_acquisition_software` | SpikeGLX | MISSING_REQUIRED_FOR_NWB | wrong Device.description |
| `spikeTimes_sorting_software` | Kilosort4 | behavioral continuous streams… | `_first_processing_module()` |

Note: sessionInfo **`lfp_probe`** row **matched** — some export paths already
resolve LFP probe correctly; **schema.json `probe` mirror** paths still hit
generic device reader.

**Root cause (`src/nwb_table_reader.py`):**
- `_device_for_datatype()` only special-cases `lfp` and `spikeWaves`; **spikeTimes
  falls through to `_first_device()`**.
- `_first_device()` returns `units.device[0]` if column exists, else **first
  device in dict iteration order** → ophys placeholder.
- `_read_processing_field()` uses `_first_processing_module()` for
  `sorting_software` — wrong module.

**Required fix — central probe resolver**

Add `_device_for_ecephys_probe(nwbfile, datatype_id)` used for all ecephys
Device.name / Device.description reads:

Priority order:
1. **`Units.device[0]`** when Units exists, `device` column populated, and
   datatype is spikeTimes or spikeWaves (or any row with notes referencing probe).
2. **`_device_for_lfp(nwbfile)`** when datatype is `lfp` (existing logic).
3. **Named device lookup:** if reverse export already knows expected probe name
   from a prior row (e.g. sessionInfo export order), use `nwbfile.devices[name]`.
4. **Heuristic:** among `nwbfile.devices`, prefer Device whose description
   contains `acquisition_software=` or `sorting_software=` key=value pairs.
5. **Exclude** devices whose name ends `_device` and description is
   `MISSING_REQUIRED_FOR_NWB` (ophys scaffolding).
6. Last resort: `_first_device()` with warning logged.

Wire `_read_device_field()` and schema/sessionInfo export for:
- `spikeTimes_probe`, `spikeWaves_probe`, `lfp_probe`
- `spikeTimes_acquisition_software`, `spikeTimes_sorting_software`
- schema mirror keys `probe`, `acquisition_software`, `sorting_software`

**`Device.description` parsing (existing helpers):**
- Use `lookup_key_value_text()` / `parse_key_value_text()` for
  `acquisition_software=SpikeGLX` and `sorting_software=Kilosort4`.
- Plain-text fallback only when table notes say single-field description.

**Remove / bypass for sorting software:**
- `_read_processing_field()` must **not** return `behavior` module description
  for `spikeTimes_sorting_software` after Task 1 retargets table to Device.
- Until table updated: follow decision doc — read sorting from **probe Device**,
  not processing.

**Files to touch:**
- `src/nwb_table_reader.py` — `_device_for_datatype`, `_read_device_field`,
  `_read_processing_field`, new probe resolver
- Any `nwb_reverse_*` modules that call device helpers directly with wrong device
- `src/tests_task4.py` — extend kitchen-sink-style fixture: ophys placeholder
  devices + Neuropixel1.0 + behavior module; assert probe/software export

**Depends on Task 2 (not blocking reader fix):**
- Forward should populate `Units.device` consistently so priority (1) is reliable.
