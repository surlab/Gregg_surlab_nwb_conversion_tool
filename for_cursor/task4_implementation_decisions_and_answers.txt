2) Stream / `<datatypeID>` discovery for traces and behTSeries
   **Finding (code + table, March 2026):**

   Forward conversion **does preserve per-stream IDs in NWB keywords today**
   (Stage 1 only — no traces/behTSeries data writers yet):

   - `src/table_placement.py::build_keyword_list()`:
     * Fixed modalities: `MODALITY_KEYWORD_MAP` maps sessionInfo column →
       keyword token (see § Keyword round-trip below).
     * Per-stream columns: if column name ends with `_traces` or `_behTSeries`
       and flag is 1, the **full column name** (the `<datatypeID>`) is appended
       to `NWBFile.keywords` unchanged (e.g. `GCaMP7f_traces`, `pupil_behTSeries`).

   **Not yet preserved anywhere in NWB for data round-trip:**
   - RoiResponseSeries / acquisition TimeSeries **object names** — no stage 3/4
     forward writer exists yet. Table row for behTSeries data still has
     `nwb_fieldname = custom_TimeSeries_name` (ambiguous — Task 1 must fix).

   **Decision (user-approved via Task 4 planning):**
   - **Canonical NWB series name = SurLab `<datatypeID>`** for both:
     * `NWBFile/ophys/RoiResponseSeries` (traces streams)
     * `NWBFile/acquisition` TimeSeries (behTSeries streams)
   - **Discovery on reverse (Task 4), priority order:**
     1. Keywords on `NWBFile` matching `*_traces` or `*_behTSeries`
     2. Named objects under ophys / acquisition whose **name equals** the keyword
     3. Fallback: scan acquisition/ophys for names ending `_traces` / `_behTSeries`
   - Task 2 must write series using that name when stage 3/4 forward conversion
     is implemented.

3) Session clock / `zero_time` (user + Task 1 clarification)
   - NWB has **no global `zero_time` field**. SurLab times share one session
     origin (t = 0); the optional `zero_time` sessionInfo column is **provenance
     only** (which stream was aligned to 0 when building SurLab files).
   - **Forward (interim):** if `zero_time` column present, write to
     `NWBFile.notes` as `SurLab zero_time=<datatypeID>` (prefix constant in
     `src/table_placement.py::ZERO_TIME_NOTES_PREFIX`).
   - **Reverse (Task 4):** parse notes for that prefix; if absent, optionally
     infer anchor stream as the one whose first timestamp ≈ 0; if column absent
     in original SurLab, omit from reverse export (optional field).
   - Do **not** treat `zero_time` as a special NWB attribute or re-zero any
     timestamps during conversion.

4) Keywords → sessionInfo boolean columns (inverse of forward)

   `src/table_placement.py::MODALITY_KEYWORD_MAP` (drift risk). Per-stream
   keywords use the full sessionInfo column name (not a separate lookup).

   **Decision (user-approved):** Add machine-readable keyword tokens to
   `sur_nwb_conversion_table.csv` via a new column **`nwb_keyword`** (see Addendum A).
   Task 2 and Task 4 load from the table — remove hardcoded dict once populated.

   Interim mapping until column exists:

   | sessionInfo column | nwb_keyword (when flag = 1) |
   |--------------------|----------------------------|
   | trialInfo          | trials                     |
   | lfp                | lfp                        |
   | spikeTimes         | spike_times                |
   | spikeWaves         | spike_waveforms            |
   | behEvents          | behavior_events            |
   | `<prefix>_traces`  | identity (keyword = column name) |
   | `<prefix>_behTSeries` | identity (keyword = column name) |

   **Reverse (Task 4):** invert fixed-modality rows via `nwb_keyword`; for
   `identity` rows, match keywords ending `_traces` / `_behTSeries` to column
   headers with value `1`. Unmatched keywords → log warning, do not invent columns.

Addendum A: `nwb_keyword` column (machine-readable keyword map)
-------------------------------------------------------------------------------
User decision: keyword tokens must be machine-readable in `sur_nwb_conversion_table.csv`,
not prose-only in documentation or a hardcoded Python dict.

**Chosen approach:** extend the existing conversion table with column
`nwb_keyword` — **not** a separate sentinel CSV file. Keeps one source of truth.

**Why not a separate `modality_keyword_map.csv`?**
A second file is only warranted if keyword edits must be isolated from the main
table. Default: one table, one column.

**Column definition**
- Name: `nwb_keyword`
- Present on sessionInfo rows where `nwb_location = NWBFile` and
  `nwb_fieldname = keywords`.
- Values:
  * Fixed modality: literal NWB keyword string (e.g. `spike_times`).
  * Per-stream rule: `identity` (keyword equals sessionInfo column name).

**Forward algorithm (Task 2, after column exists)**
For each sessionInfo column with value 1 (or truthy):
1. Find table row for that column (or matching per-stream rule row).
2. If `nwb_keyword` is a literal token → append to `NWBFile.keywords`.
3. If `nwb_keyword` is `identity` and column ends with `_traces` or
   `_behTSeries` → append column name to keywords.
4. Deduplicate and sort keywords.

**Reverse algorithm (Task 4)**
For each entry in `NWBFile.keywords`:
1. If keyword matches a fixed-modality `nwb_keyword` token → set that
   `fieldname_surlab` column to `1`.
2. If keyword ends with `_traces` or `_behTSeries` → set column named keyword to `1`.
3. Else log warning (unknown keyword).

**Migration:** until Task 1 adds the column, code may fall back to
`MODALITY_KEYWORD_MAP` with a deprecation warning in the log.

Addendum B: Reverse fallbacks (`nwb_alt_fieldnames` + `reverse_mapping/*.csv`)
-------------------------------------------------------------------------------
User decision (Task 1 spec, April 2026): support reverse from non–SurLab-native NWB
without bloating the primary table.

**Primary table — one column, reverse-only:**
- `nwb_alt_fieldnames` — semicolon-separated names on **same** `nwb_location` as
  primary (e.g. `brain_area;location`). Optional `/location|field` escape for rare
  cross-container renames. Forward ignores.

**Ecosystem packs — separate CSVs:**
- Directory: `reverse_mapping/` (e.g. `allen.csv`, `ibl.csv`).
- Join key: **`fieldname_surlab`** (SurLab names are unique enough within the table).
- Columns: `fieldname_surlab`, `priority`, `nwb_location`, `nwb_fieldname`,
  `linkage_note`, `notes`.
- Loaded **only when user specifies** ecosystem (e.g. `--reverse-ecosystem allen`).
  Default reverse = primary + inline `nwb_alt_fieldnames` only (generic path).

**Read order:** primary (with linkage) → `nwb_alt_fieldnames` → ecosystem CSV(s)
if requested. Primary wins; warn if primary and fallback both non-empty and differ.
Always write canonical `fieldname_surlab`. Log source in reverse report.

**Task 4:** implement loader for ecosystem files; extend read helper for alias column.

See `reverse_mapping/README.md`.

Addendum C: Stream-scalar dual-write + software field parsing (Task 4 fix)
-------------------------------------------------------------------------------
Spec: stream scalars are canonical as sessionInfo columns `{datatypeID}_{field}`.
`{datatypeID}_schema.json` is a legacy optional mirror. Reverse writes both.

**Device.description parsing:**
- If description matches `key=value; ...`, parse keys:
  - `acquisition_software` → `spikeTimes_acquisition_software` + schema `acquisition_software`
  - `sorting_software` → `spikeTimes_sorting_software` + schema `sorting_software`
- Else if plain software name → acquisition_software only.
- Prefer processing-module description for sorting_software; fall back to parsed
  `sorting_software=` from Device.description.
- Never dump the raw combined Device.description into sessionInfo.

**Modality flags:** absent keyword → write `0` (not blank) for fixed modalities
(lfp, spikeWaves, behEvents, trialInfo, etc.).

**Absent modalities:** if lfp keyword/modality absent → `lfp=0`, leave `lfp_*`
sessionInfo columns empty; do not invent `lfp_schema.json` from spikeTimes device.
